# Reproducibility and Technical Requirements

## 1. Required repository inputs

The model requires the following fixed files in its own directory:

- `Data/input_manifest.csv`
- `Data/reference/release_reference.json`
- `Data/source_raw/cbo_spending_detail_2026_06.xlsx`
- `Data/source_raw/jct_tax_expenditures_2025_2029.pdf`
- the complete `Data/fiscal_policy_data_pack_v1/` directory

The two fixed files under `Data/source_raw/` are validated against SHA-256 values in `Data/input_manifest.csv`.

The policy-data pack carries its own source manifest, coverage audit, pack manifest, and file hashes. Those records are checked during execution.

These fixed files define the published model vintage. Replacing them with newer source vintages changes the reproduction target.

## 2. R and solver environment

The validated release was run with:

- **R 4.6.1** (`R version 4.6.1 (2026-06-24 ucrt)`);
- **HiGHS 1.14.0.2** through the R `highs` package;
- **x86_64-w64-mingw32**;
- **8 HiGHS solver threads**;
- requested relative MIP gap **0**.

The script does not hard-code Windows paths and is written to resolve its own directory at runtime. The validated platform is recorded here so a reproducer can distinguish a platform difference from a model difference.

The script accepts `FISCAL_SOLVER_THREADS` as an environment variable. If it is not supplied, the script chooses a bounded thread count from the detected hardware and later applies its memory-aware thread limits.

The script accepts `FISCAL_EVIDENCE_MODE`. The validated release uses the default:

```text
OFFICIAL_OLDER
```

The other recognized values are `OFFICIAL_CURRENT` and `EXPLORATORY`.

For exact restoration of the validated package graph, generate an `renv.lock` from the validated R environment and commit it with the model. A lockfile should be generated by `renv` from that environment rather than constructed manually.

## 4. API credentials

External historical validation requires the following API keys:

- `BEA_API_KEY`
- `BLS_API_KEY`
- `FRED_API_KEY`

The script is configured to require those validation checks for the validated release. If one of these keys is absent, the model stops rather than silently skipping the corresponding external validation.

`CENSUS_API_KEY` is recognized but is not required by the current core model.

A local `.Renviron` file can define these variables:

```text
BEA_API_KEY=your_key_here
BLS_API_KEY=your_key_here
FRED_API_KEY=your_key_here
CENSUS_API_KEY=your_key_here
```

Do not commit a populated `.Renviron` file. The included `.Renviron.example` contains variable names only.

## 5. Network access

The model uses live official-source queries for validation and source acquisition. A reproducing environment therefore requires outbound HTTPS access to the relevant federal data endpoints.

The fixed CBO spending-detail workbook, JCT tax-expenditure PDF, policy-data pack, and release reference are stored in the repository so those specific audited inputs do not depend on successful rediscovery at runtime.

## 6. Running in RStudio

Open the model directory and run:

```r
source("federal_fiscal_optimizer.R", echo = TRUE)
```

The script resolves the directory containing itself, so it can also be sourced when RStudio's current working directory is elsewhere.

## 7. Running from a shell

With R available on the system path:

```text
Rscript federal_fiscal_optimizer.R
```

## 8. Startup checks

Before the fiscal optimization proceeds, the script:

1. checks and, when authorized, installs required R packages;
2. resolves repository-relative paths;
3. validates recognized evidence-mode settings;
4. verifies the fixed repository inputs and their hashes;
5. validates required API credentials;
6. performs a small known MILP through the `highs` R interface to confirm that the solver interface is functioning.

Failure of a required startup or validation check stops the run.

## 10. Reproduction reference

`Data/reference/release_reference.json` stores the numerical and exact-membership reference used by the model's release-parity check.

The validated release reference is:

- active solver candidates: **1,116**;
- selected policies: **21**;
- implementation-complexity score: **31.996850**;
- central debt/GDP, 2036: **86.335057%**;
- central debt/GDP, 2046: **66.549700%**;
- worst required-scenario debt/GDP, 2036: **89.991493%**;
- worst required-scenario debt/GDP, 2046: **74.662096%**;
- Social Security actuarial improvement: **4.50% of taxable payroll**.

The reference also contains the exact selected candidate identifiers. A successful release-parity test therefore checks package membership as well as headline numerical metrics.

## 11. Numerical tolerances

The principal configured numerical controls are:

| Control | Value |
| --- | ---: |
| Requested HiGHS relative MIP gap | 0 |
| Post-solve relative gap audit | `1e-8` |
| Post-solve absolute objective-gap audit | `1e-6` |
| Primal feasibility tolerance | `1e-7` |
| Dual feasibility tolerance | `1e-7` |
| Accepted constraint residual | `1e-5` |
| Accepted variable-bound residual | `1e-6` |
| Accepted integrality residual | `1e-6` |
| Independent simulation tolerance | $2 billion |
| Debt identity tolerance | $0.01 billion |
| Debt/GDP reconstruction tolerance | 0.02 percentage point |
| CBO debt-service-kernel validation tolerance | $3 billion |

The post-solve gap tolerances are numerical audits applied only after HiGHS reports `Optimal`. They do not permit unfinished solves to be treated as optimal.

## 12. Validation sequence

The validated model requires successful completion of:

- CBO baseline accounting identities;
- Treasury, FRED, BEA, and BLS historical cross-checks;
- reciprocal leave-one-out validation of the CBO debt-service kernel;
- reconstruction checks for the CBO macro sensitivity profiles;
- current CBO option-index validation;
- current Social Security actuarial-target validation;
- policy parameterization validation;
- score-basis contract checks;
- protection regression;
- material-overlap validation;
- solver terminal-status and numerical-gap audits;
- independent post-solve simulation;
- exact release-reference membership and metric checks.

These checks are part of the executable model rather than manual review steps.

## 13. Validated computational scale

The Expanded package-ready MILP contains **21,411 variables**, **21,922 constraints**, and **1,568,494 nonzero coefficients**. The validated model evaluates five required robustness scenarios inside each applicable MILP.

The complete validated analysis attempted **121 MILP solves**. Of those, **106** terminated `Optimal` and **15** terminated `Infeasible` in feasibility or counterfactual diagnostics. No solve ended with an unfinished terminal status.

The model uses memory-aware schedule reduction for complexity solves. Candidate policies are not removed to reduce memory. The reduction removes only timing paths that are proven duplicated or componentwise dominated for the same policy.

## 14. Runtime files

A run writes working and audit material locally, including caches, acquired validation data, solver diagnostics, source-provenance records, policy and scenario tables, independent-simulation results, and the presentation plot.

The principal runtime locations are:

- `Cache/`
- `Data/validation_raw/`
- `analysis_output/`
- `analysis_output.zip`

These generated outputs are not required to obtain the source code or fixed reproduction inputs from the repository. A fresh run regenerates them.

## 15. Reproduction standard

A successful reproduction should:

- complete the required validation pipeline;
- reproduce the exact selected candidate membership;
- reproduce the release-reference metrics within the configured tolerance;
- satisfy the required debt and Social Security constraints;
- pass the protection and material-overlap checks;
- pass the solver optimality and numerical-gap checks for every solve reported as optimal;
- independently re-simulate every retained package within the configured tolerance.

Differences caused by a changed official source vintage, changed model source, changed fixed input, or changed evidence mode are not reproductions of this published model.
